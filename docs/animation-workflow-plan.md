# snowlink-studio AI 애니메이션 기능 적용 계획

2026년 10월 1일 작성. 상태는 기능 설계이며 구현 완료 문서가 아니다. 기존 [제작 기획](production-plan.md)의 채널별 설정, 세션 메모리, 단계별 승인, 최대 3회 재생성 요구를 구체화한다. 이번에는 실행 코드나 실제 생성 작업을 변경하지 않는다.

목표는 원고를 캐릭터와 장면 자료에 연결하고, 실제 움직이는 영상의 여러 후보에서 쓸 구간을 선택해 한 작품으로 완성하는 것이다. [추가 참고 영상](https://www.youtube.com/watch?v=pRRUFTocBes)의 확인 범위와 시간대별 근거는 [레퍼런스 분석](reference-analysis.md#네-번째-영상의-역할)에 기록했다. 아래 기능, 데이터 구조, 개발 순서는 snowlink-studio에 맞춘 설계 제안이다.

## 이번에 구체화할 기능

| 기능 | 웹에서 할 수 있는 일 | 저장할 결과 |
| --- | --- | --- |
| 역할이 있는 참조 자료 | 인물의 얼굴·전신·의상, 배경, 소품, 음성을 구분해서 배역과 컷에 연결 | 자산 ID·버전·역할, 배역별 참조 연결 |
| 대사와 행동 편집 | 화자, 발화 순서, 대사 뒤 반응, 카메라 변화를 컷별로 편집 | 대사 ID, 행동 이벤트, 시간·순서 제약 |
| 초안과 최종 후보 | 지원되는 낮은 해상도로 검토하고 선택한 명세로 최종 후보 생성 | 입력 명세 스냅샷, 후보 간 계보, 재생성 횟수 |
| 테이크 비교와 부분 채택 | A의 앞부분과 B의 뒷부분을 선택해 하나의 컷으로 구성 | 테이크별 사용 시작·종료 시각, 편집 순서 |
| 연결 검토 | 실제 채택한 끝 프레임과 인물 상태로 다음 컷·구간 제작 | 연결 기준 프레임, 상태 요약, 의존 관계 |
| 완성본 검토 | 영상·대사·자막·효과음의 합성 결과를 연속 재생하고 승인 | 편집 버전, 검토 항목, 출력물·승인 이력 |

캐릭터·배경·소품과 채널 스타일은 카드뉴스에서도 재사용한다. 카드뉴스 문안·배치·승인 버전은 영상과 별도로 유지한다.

## 현재 코드에서 재사용할 부분

| 현재 구현 | 재사용 방식 | 추가로 필요한 부분 |
| --- | --- | --- |
| `server/store.mjs`의 캐릭터·제작 기획 | 기존 ID와 기획을 유지 | 채널·세션 참조, 여러 시트와 버전, 역할 구분 |
| `server/cuts.mjs`의 대화 수정·revision·되돌리기 | 수정안과 편집 이력의 기초 | 한 컷의 여러 인물, 대사 ID, 시퀀스, 승인 상태 |
| `vendor/ima2-ui/src/StudioBridge.tsx`와 `studio-production.ts` | 공용 캐릭터를 생성 참조로 전달 | 생성 결과를 특정 컷의 베이스 이미지·테이크로 연결 |
| `server/modelSettings.mjs`의 작업별 모델 | 작업실 기본 모델을 제공 | 채널·작품별 스냅샷, 모델과 입력 방식에 따른 기능 검사 |
| ima2의 `/api/video`와 SSE | 생성·진행 상황·결과 파일 수신 | 작품·컷·테이크·작업 ID 연결과 재접속 복구 |
| ima2의 `/api/video/extend` | 마지막 프레임을 이용한 후속 생성 | 편집에서 채택한 종료 시점의 프레임 추출 |
| `server/render.mjs`와 ShortGPT 출력 | 기존 무음 콘티 미리보기 유지 | 실제 영상·오디오 파일을 사용하는 최종 합성 경로 |

현재 컷은 한 명의 `characterId`와 1~30초 길이를 저장한다. 이것을 그대로 영상 생성 요청으로 보내면 여러 인물과 모델별 길이 제한을 처리하지 못한다. 기획 컷과 실제 생성 컷을 분리하고 기존 데이터는 변환 계층을 통해 읽는다.

## 모델 능력에 맞춘 생성 경로

다음은 이번 조사에서 확인한 **현재 로컬 코드의 제한**이다. 외부 서비스의 영구 사양이나 실제 생성 성공을 보장하는 값이 아니다. `/api/models`의 일반 목록만으로 모든 조건을 판단하지 않고 `lib/imageModels.ts`, `lib/grokVideoAdapter.ts`의 모드별 검증과 일치시킨다.

| 항목 | 현재 연결에서 확인한 조건 | 설계에 반영할 처리 |
| --- | --- | --- |
| GPT OAuth | 로컬 이미지 경로에서 기획과 이미지 생성에 사용, 영상 모델 목록은 비어 있음 | 원고·명세·시트·베이스 이미지 역할에 연결 |
| Grok 생성 길이 | 전체 정규화는 1~15초, 참조 모드 기본 모델은 최대 10초·1.5는 최대 15초 | 30~60초 구간을 생성 가능한 컷들로 분할 |
| 이미지 참조 | 로컬 검증은 최대 14장 | 얼굴·의상·배경을 자동 배정하되 초과하면 선택 요청; 자료를 조용히 버리지 않음 |
| 음성 참조 | 1.5의 `referenceAudios`는 최대 3개의 voice ID | 화자별 지원 voice ID를 연결; 임의 음성 파일 업로드·복제와 구별 |
| 생성 모드 | `image-to-video`는 시작 이미지, `reference-to-video`는 여러 참조 이미지; 동시 입력 조합은 거절 | 첫 프레임 고정과 다중 참조 중 의도에 맞는 모드를 명시 |
| 해상도 | 참조 모드는 480p·720p, 1080p는 1.5의 허용된 I2V/T2V 경로에 한정 | 선택 모델·모드에서 가능한 초안/최종 해상도만 노출 |
| 영상 연장 | 마지막 프레임 I2V와 native 연장 API가 별도이며 지원 모델도 다름 | 연결 방식을 기록하고 지원 여부를 검사한 뒤 실행 |

표의 숫자를 화면마다 복사하지 않는다. 지원 모델, 입력 역할, 모드별 길이·참조 개수·해상도를 하나의 capability 응답으로 정규화한다. 개별 기능은 `지원`, `미지원`, `미확인`을 구분한다. 오디오만 넣는 요청은 현재 route와 adapter의 검증이 일치하지 않아 초기 지원 범위에서 제외하고 계약을 먼저 정리한다.

기본 흐름은 캐릭터·배경 자료로 장면의 베이스 이미지를 만든 뒤 이를 시작 프레임으로 영상화하는 것이다. 다중 참조 모드가 필요한 컷은 별도로 선택한다. 이 경우 베이스 이미지를 참조로 넣더라도 정확히 첫 프레임으로 고정됐다고 표시하지 않는다.

첫 프레임과 여러 참조, 음성을 모두 함께 사용할 수 있다는 보장은 하지 않는다. 특히 기존 마지막 프레임 연장 경로는 음성 참조 ID를 전달하지 않으므로 캐릭터 목소리가 이어진다고 가정하지 않고 어댑터 확장과 별도 검증 항목으로 둔다.

GPT OAuth·Grok OAuth 방침을 유지한다. 참고 영상에 등장하는 외부 서비스나 요금제는 도입하지 않으며, 그 서비스의 자료 수·생성 길이·무제한 요금 설명을 현재 모델에 적용하지 않는다.

## 화면과 작업 흐름

기존 왼쪽 메뉴와 ima2의 생성 UI는 유지한다. 제작 보드에서 작품을 열면 `기획 대화 → 원고 → 배역·자료 → 시퀀스 → 테이크·편집 → 완성본`을 작품 내부 단계로 제공한다. ShortGPT 컷 편집은 같은 작품·시퀀스 데이터를 읽도록 연결한다.

1. 채널 선택 후 세션 대화에서 주제·언어·분량·스타일을 확정한다. 채널의 고정 설정과 이번 작품의 예외를 함께 표시한다.
2. 원고를 승인하면 사건·장소·감정 전환을 기준으로 시퀀스를 제안한다. 시퀀스마다 필요한 배역과 자료를 확인한다.
3. 배역에 고정 캐릭터 또는 신규 캐릭터를 지정한다. 얼굴, 전신·삼면도, 의상, 표정, 음성 연결을 관리하고 캐릭터 버전을 승인한다.
4. 시퀀스를 모델 길이에 맞는 생성 컷으로 나눈다. 컷 카드에서 베이스 이미지, 행동, 대사, 카메라, 종료 상태를 수정한다.
5. 장면 이미지를 승인한 뒤 `초안 생성`을 실행한다. 완료된 컷부터 재생하며 실패 사유와 수정안을 기록한다.
6. A/B 테이크를 비교하고 사용할 구간을 선택한다. 해상도를 바꾸어 재생성할 경우 새 후보로 비교한다.
7. 구간을 이어 재생하고 연결을 확인한다. 다음 구간은 선택된 끝 프레임과 이야기 상태에서 시작한다.
8. 완성본을 승인하면 새로 추가할 게시 대기 상태로 넘긴다. 실제 플랫폼 OAuth·예약 게시는 별도 구현 단계다.

생성 화면에는 선택한 작품·시퀀스·컷을 표시하고 `이 컷의 베이스 이미지로 사용`, `이 컷의 테이크로 연결` 동작을 추가한다. 원본 갤러리 파일을 수정하거나 이동하지 않고 자산 참조로 연결한다.

## 참조 자료와 대사 타이밍

자산은 업로드 순서가 아니라 역할로 지정한다. 예를 들어 `하린 얼굴`, `하린 겨울 외투`, `카페 배경`, `하린 음성`을 배역에 연결한다. 생성 어댑터가 실제 요청의 이미지 순서와 프롬프트 표기를 함께 만든다. 자료 순서를 바꿔도 다른 인물의 얼굴이나 목소리가 연결되지 않아야 한다.

다음은 동작을 구조화하는 **새 설계 예시**이며 참고 영상의 원고가 아니다.

| 사건 | 명세 예시 | 검토 항목 |
| --- | --- | --- |
| 하린이 초대장을 건넴 | 컷 시작 후 손을 내밀고 초대장을 우진에게 전달 | 소품의 소유자가 올바르게 바뀌는가 |
| 우진이 질문함 | 화자 우진, 지정된 한 문장, 연결된 voice ID | 문장·화자·목소리가 맞는가 |
| 하린이 놀람 | 질문 대사가 끝나는 시점을 기준으로 반응 시작 | 상대 대사가 끝나기 전에 반응하지 않는가 |
| 다음 컷으로 연결 | 우진 오른손의 초대장과 두 사람 시선 유지 | 실제 채택한 끝 프레임과 일치하는가 |

정확한 초 단위 요청과 `대사 종료 후 반응` 같은 상대 순서를 모두 저장한다. 생성 모델에 전달한 지시는 목표이며 준수 여부는 별도 검토 상태다. 초기 버전은 사용자가 발화·반응 마커를 찍고 교정한다. 이후 사용할 수 있는 음성 인식·정렬 기능을 검증해 보조 검사로 추가한다. 검사 모델이 없는데 자동 음성 검수가 완료됐다고 표시하지 않는다.

## 초안과 테이크 편집

초안은 지원되는 낮은 해상도로 생성한다. 최종 후보에는 초안에서 승인한 캐릭터 버전, 이미지, 프롬프트, 모델, 타이밍 명세를 복사한다. 고화질 재생성은 같은 움직임을 보존하는 업스케일이 아니므로 최종 후보도 다시 검토한다. 별도 업스케일 기능은 실제 지원을 확인하기 전에는 제공하지 않는다.

기존 요구의 기본 해석은 **최초 생성 1회 + 자동 재생성 최대 3회**다. 저화질 수정과 고화질 재생성도 같은 컷의 재생성 횟수에 포함한다. 초안 단계에서 한도를 다 썼으면 자동으로 최종 생성을 추가하지 않고 사용자 검토로 전환한다. 네 후보를 미리 모두 생성하지 않고 필요한 만큼 생성한다.

테이크는 원본 전체를 보존한다. 편집 선택은 `{takeId, sourceIn, sourceOut}`의 목록으로 저장하며 같은 컷 안에서도 여러 테이크의 구간을 사용할 수 있다. 사용자가 앞부분과 뒷부분을 고르면 전체 편집 시간축과 대사·자막 위치를 다시 계산한다. 모델의 요청 길이 대신 결과 파일에서 측정한 실제 길이를 사용한다.

대사 중간 자르기, 음성 겹침, 인물 자세가 튀는 연결을 표시한다. 별도 트랙이 있는 경우 원음, 내레이션, 효과음, 배경음의 음소거·볼륨을 구분한다. 생성 영상에 이미 합쳐진 소리는 컷 단위로 제어하고 효과음·음악 중복을 수동 검토한다. 자동 음성 분리까지 구현됐다고 가정하지 않는다.

통신 오류 재시도와 새로운 생성 후보는 별도 기록한다. 업스트림이 접수했는지 불확실하면 `상태 확인 필요`로 두고 자동 재전송하지 않는다. 같은 요청이 중복 생성되지 않도록 로컬 작업 ID와 업스트림 작업 ID를 저장한다.

## 긴 영상과 연결 상태

30~60초 구간은 여러 선택 클립으로 구성한다. 다음 구간의 기준은 마지막 원본 테이크의 끝이 아니라 **편집에서 실제 선택한 종료 시각의 프레임**이다. 이를 추출하고 인물, 의상, 소품, 위치·시선, 마지막 대사, 미해결 사건, 카메라 상태와 함께 저장한다.

동작이 이어지는 연결과 장소·시간이 바뀌는 장면 전환을 구분한다. 모든 컷을 마지막 프레임으로 강제 연결하지 않는다. 배경만 바꾸는 전환, 반응 컷, 소품 컷도 이야기 흐름에 맞게 배치할 수 있어야 한다.

이전 컷의 선택 구간을 바꾸면 그 컷을 참조한 후속 컷만 `연결 재검토`로 표시한다. 이미 생성한 후속 영상을 지우지 않는다. 웹 연속 재생은 검토용이고, 최종 합성 파일은 해상도·비율·프레임률·오디오 규격을 맞춰 별도로 출력한다.

## 저장 구조와 변경 범위

| 데이터 | 핵심 필드 |
| --- | --- |
| `AssetVersion` | 자산 ID, 버전, 종류·역할, 파일 참조, 소유 채널, 연결 배역 |
| `Sequence` | 작품·구간 ID, 사건, 장소·시간, 배역, 원고 버전 |
| `ShotSpec` | 시퀀스 ID, 복수 배역, 이미지 버전, 대사·행동 이벤트, 시작·종료 상태, 생성 설정 |
| `Take` | 컷 ID, 명세 스냅샷, 생성 시도 번호, 로컬·업스트림 작업 ID, 파일 참조, 실제 길이·해상도·음성 정보 |
| `EditSelection` | 컷 ID, 선택 구간 목록, 전환, 오디오 설정, 편집 버전 |
| `Approval` | 대상 ID·버전, 원고/캐릭터/이미지/완성본 단계, 승인 시각, 무효화 사유 |
| `ContinuityLink` | 이전 선택 버전, 선택 종료 프레임, 다음 컷 ID, 상태 요약, 재검토 상태 |

10월 1일에는 현재 파일 저장 방식에 맞춘 버전 문서와 작업 기록을 제안했다. 10월 3일 추가된 노드 실행·복구 요구를 반영한 [PRD](PRD.md)와 [노드 워크플로 설계](node-workflow-design.md)는 SQLite 등 트랜잭션을 지원하는 저장소를 우선 제안한다. 이 저장 방식과 실행기 제안은 아직 구현되지 않았다. revision 충돌 검사를 유지하고, 기존 `studio.json`과 컷 파일은 백업 후 반복 실행 가능한 변환으로 ID와 이력을 보존한다. 큰 이미지·영상은 문서나 DB 안에 base64로 넣지 않는다.

제안하는 구현 경계는 다음과 같다. 아래 파일·API는 아직 존재하는 기능으로 표시하지 않는다.

| 제안 위치 | 책임 |
| --- | --- |
| `server/productionAssets.mjs` | 자산 버전, 배역별 자료 연결, 공용 갤러리 참조 |
| `server/sequences.mjs` | 시퀀스·컷·타이밍 명세 검증, 기존 컷 호환 읽기 |
| `server/productionJobs.mjs` | 생성 큐, 시도 상한, 작업 ID 매핑, 재접속 복구 |
| `server/productionTimeline.mjs` | 테이크 구간 선택, 실제 길이 검증, 연결 프레임 |
| `server/productionApprovals.mjs` | 버전별 승인과 수정 영향 계산 |
| `public/modules/production-workspace.js` | 기존 공용 컴포넌트로 작품 단계·테이크 편집 표시 |

새 쓰기 API는 작품·컷 ID와 revision을 받아 명세 수정, 승인, 생성, 선택을 분리한다. 대화 AI는 허용된 필드의 수정안을 반환하며, 원본 파일 경로나 실행 명령을 직접 지정하지 않는다. 수정으로 재생성이 필요한 컷과 기존 승인에 미치는 영향을 먼저 보여준다.

## 개발 순서와 완료 기준

아래 표는 애니메이션 기능 내부의 의존 순서다. 카드뉴스와 병행하는 전체 제품 릴리스 순서와 출하 조건은 2026-10-03 [PRD](PRD.md)의 R1~R4를 기준으로 한다.

| 순서 | 범위 | 완료 기준 |
| --- | --- | --- |
| 1 | 채널·세션 기반과 역할별 참조 자료 | 기존 기획 이관, 복수 인물·의상·배경 연결, 채널 간 자료 격리, 카드뉴스에서도 같은 자산 재사용 |
| 2 | 시퀀스·컷 명세와 단계별 승인 | 원고에서 컷을 나누고 대사·행동을 수정, 승인 버전에만 생성 허용 |
| 3 | ima2 결과 연결과 초안·테이크 | 컷에서 생성한 결과가 해당 컷으로 돌아옴, 모델·모드 제한 검사, 재생성 상한과 실패 복구 |
| 4 | 부분 채택과 영상·음성 합성 | 서로 다른 테이크에서 구간을 채택, 미리보기와 실제 출력의 길이·순서가 일치 |
| 5 | 구간 연결과 다음 구간 생성 | 30~60초 구간 두 개를 연속 재생, 실제 선택 종료 프레임으로 다음 구간 준비, 변경 영향 표시 |
| 6 | 채널 운영 자동화 연결 | 사용자 승인된 완성본만 게시 대기열에 전달; 플랫폼 연결·게시 구현은 별도 검증 |

첫 검증 작품은 두 인물, 한 장소, 짧은 대사 교환과 반응이 있는 3개 컷으로 제안한다. 캐릭터 일관성, 대사 순서, 소품 이동, 테이크 부분 교체를 확인한다. 그다음 30~60초 완성 구간과 다음 구간 연결을 검증한다. 테스트를 위한 실제 생성은 별도 실행 단계이며 이번 조사에서 호출하지 않았다.

자동 검사는 저장·복구·revision 충돌, 참조 역할 매핑, 잘못된 입력 조합, 재시도 중복 방지, 승인 버전 변경 영향, 영상 구간 경계와 출력 길이를 다룬다. 인물 외형과 연기·목소리·감정 타이밍은 사람이 재생해서 승인한다.

## 현재 남은 결정

하루 목표량의 전체/채널별 적용 범위는 미정으로 유지한다. 10월 4일 답변에 따라 본인용 도구, AI 대화로 노드 초안 구성, 주제별 가변 카드뉴스 분량과 [트렌드 분석 근거 축적](trend-intelligence-plan.md)을 적용한다. 주제·언어·스타일·캐릭터 정책은 채널·세션 설정으로 처리한다. 초안/최종 해상도와 음성 방식도 채널 기본값을 두고 작품·컷에서 바꿀 수 있게 제안한다.
