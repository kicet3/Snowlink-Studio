# snowlink-studio 시장·경쟁 제품 조사

조사 기준일: 2026-10-03 · 목적: [PRD](PRD.md)의 제품 범위와 개발 우선순위 결정

범위 갱신 2026-10-04: 사용자가 본인만 쓰는 개인 도구로 확정했다. 경쟁 제품 조사는 기능 선택의 참고로 유지하고, 팀·외부 고객·유료화 검증은 현재 로드맵에서 제외한다. 트렌드 분석 자료를 축적해 생성에 활용하는 요구는 [별도 설계](trend-intelligence-plan.md)에 반영했다.

공식 제품 페이지·문서·가격표를 확인한 데스크 리서치다. 로그인 후 실사용, 동일 프롬프트의 품질·속도·비용 벤치마크, 고객 인터뷰는 수행하지 않았다. 공급자가 제공한다고 설명한 기능과 snowlink-studio에 대한 판단을 구분한다. 문서에 없는 기능은 `없음`으로 단정하지 않는다.

## 1. 조사 결론

노드 기반 AI 제작은 이미 여러 제품이 제공하는 인터페이스다. 노드 화면을 구현하는 것만으로는 경쟁 우위가 충분하지 않다는 판단이다. 생성 전 기획과 생성 후 편집·재사용까지 연결하는 방향도 확인된다.

snowlink-studio의 우선 가설은 **채널별 기억과 출연진을 유지하면서 영상·카드뉴스를 함께 만들고, 승인된 버전만 운영 단계로 넘기는 작업실**이다. 같은 범위의 경쟁 제품이 전혀 없다는 주장은 하지 않는다. 기존 생성 도구들과 경쟁할 부분은 모델 숫자보다 자료 전달, 반복 수정, 검토, 채널 전환에 드는 수고다.

### ComfyUI에서 참고할 범위

App Mode는 노드를 편집하지 않고도 선택한 입력으로 워크플로를 실행하도록 한다. snowlink-studio도 모든 사용자에게 빈 캔버스를 먼저 제시하기보다 채널·주제·캐릭터·길이를 입력하는 기본 화면을 제공하는 편이 적합하다. 이는 해당 기능을 보고 도출한 UX 제안이다. [공식 App Mode 문서](https://docs.comfy.org/interface/app-mode)

ComfyUI의 부분 실행 문서는 선택한 **출력 노드**에 필요한 경로를 실행하는 방식이다. 임의의 모든 노드에서 같은 방식으로 실행된다고 확대 해석하지 않는다. snowlink-studio에서는 실행 전 필요한 선행 노드와 승인을 보여주는 `이 결과까지 실행`으로 설계한다. [공식 부분 실행 문서](https://docs.comfy.org/interface/features/partial-execution)

현재 subgraph 문서의 blueprint 인스턴스는 서로 독립적으로 편집된다. 이를 중앙 템플릿을 수정하면 기존 작품까지 자동 갱신되는 기능으로 오해하지 않는다. snowlink-studio도 작품에 사용한 템플릿 버전을 고정하고 업그레이드 시 차이를 보여준다. [공식 Subgraph 문서](https://docs.comfy.org/interface/features/subgraph)

### 생성 이후의 편집도 비교 기준

FLORA의 2026-07-03 발표는 캔버스 내부에서 자르기·배치·완성 영상 렌더링을 제공한다고 설명한다. 따라서 snowlink-studio의 영상 노드는 결과 URL만 반환하는 것으로 끝내지 않고 타임라인의 채택 구간과 이어져야 한다. [공식 업데이트](https://flora.ai/updates/in-canvas-video-editor-a-faster-canvas)

Runway는 출력 잠금과 실행 제어에 더해 프레임 추출·영상 이어 붙이기·오디오 처리를 설명한다. snowlink-studio에서는 승인된 자산 보존과 컷 교체에 필요한 동작부터 구현한다. 공개한 워크플로를 API로 실행하는 구조도 서버 실행 경계를 설계할 때 참고할 수 있다. [Workflows 도움말](https://help.runwayml.com/hc/en-us/articles/45763528999699-Introduction-to-Workflows), [Workflows API](https://dev.runwayml.com/workflows)

LTX Studio는 이야기 중심 도구인 동시에 Flows도 제공한다. `ComfyUI는 노드, LTX는 스토리보드`라는 상호 배타적 분류는 부정확하다. 캐릭터·스토리보드·노드를 결합하는 기능도 경쟁 범위에 포함해야 한다. [LTX Studio 요금표](https://ltx.io/studio/pricing)

## 3. 요금과 운영 모델

미국 달러 공개 표시 가격이며 세금·지역·할인·계약·결제 화면은 검증하지 않았다. 월 환산 연간 요금과 월 결제를 구분한다. 서로 다른 모델·해상도·길이의 크레딧을 영상 한 편의 원가로 환산하지 않는다.

시사점은 구독 여부와 실제 생성 자원을 따로 다뤄야 한다는 것이다. snowlink-studio에서 OAuth로 로그인하더라도 호출 한도·대기·재생성·외부 서비스 지원을 추적해야 한다. 비용 정보가 없는 작업은 `0원`이 아니라 `확인 불가`로 표시한다. 경쟁 제품의 유료 모델을 이번 조사만으로 도입하지 않는다.

개인 도구이므로 자체 구독료·고객 과금 구조는 설계하지 않는다. 경쟁 제품의 요금은 개인 제작에 드는 자원과 대체 도구 비용을 이해하는 참고 자료로만 사용한다.

## 6. 개인 제작 흐름 검증

1. 본인의 실제 한 편 제작 과정을 기준으로 도구 이동·검토·재생성 시간을 기록한다. 외부 고객 인터뷰를 개발의 선행 단계로 두지 않는다.
2. 두 인물·3개 컷의 대화 영상과 같은 소재의 카드뉴스 묶음을 공통 검증 과제로 삼는다. 사람이 조작한 시간, 모델 대기 시간, 후보 수, 최종 채택률을 분리한다.
3. 기본 시작 방식은 사용자 결정대로 AI 대화로 확정한다. 기획에서 누적 후킹 분석을 사용하고 노드로 이동해 수정·완성할 수 있는지 검증한다.
4. 일주일 반복 제작으로 채널 기억·분석 자료·자산 재사용의 효과와 승인 대기 병목을 측정한다. 카드뉴스는 주제별로 분량을 정하고 장수 채우기를 위해 문안이 늘어나지 않는지 확인한다.
5. 원고에 채택한 근거와 내 채널의 실제 성과를 연결한다. 영상에서 관찰한 구성과 성과의 인과관계를 단정하지 않고 사용자 검토·다음 기획에 사용한다.

반복 검증에서 드러난 병목에 따라 타임라인·참조 일관성 또는 메모리·템플릿·부분 실행의 순서를 조정한다. 수집 API 접근성과 게시 API 권한은 각 플랫폼 통합을 구현할 때 다시 확인한다. 위 항목은 검증 계획이며 실제 측정 결과가 아니다.
