# 증거와 평가 기준

검사의 목적은 결과를 반박할 수 있는 관찰을 확보하는 것이다. 파일이나 명령이 존재한다는 사실과 주장한 업무가 완료되었다는 사실을 구분한다.

## 증거의 연결

| 확인할 주장 | 적합한 근거 | 충분하지 않은 근거 |
|---|---|---|
| 소스 코드가 특정 동작을 구현함 | 경로, 심볼, 관련 코드 위치 | 파일명 추정 |
| 명령이 성공함 | 실행한 명령, 종료 코드, 출력 | 실행 계획 |
| 문서의 수치가 맞음 | 입력 레코드, 집계식, 비교 값 | AI의 재독 후 동의 |
| 사용자가 UI에서 작업을 끝낼 수 있음 | 실제 입력·조작·기대 결과 | HTTP 200 또는 스크린샷 파일 존재 |
| 수정으로 문제가 해결됨 | 같은 실패 사례의 재실행과 결과 | 규칙을 추가했다는 사실 |

수치·개수·형식은 기존 도구나 간단한 코드로 대조한다. 의미·품질은 평가 기준과 구체적 관찰을 함께 남긴다. 별도 평가자가 있어도 그 판단만으로 사실 검증을 대체하지 않는다.

## 상태

- **통과:** 기대 결과를 실제 근거로 확인했다.
- **실패:** 관찰 결과가 기대와 다르다.
- **미확인:** 실행하지 못했거나 판정에 필요한 근거가 없다.
- **해당 없음:** 해당 조건이 이 입력에는 적용되지 않으며 이유를 설명할 수 있다.

선택 검사가 미확인인 것과 필수 결과가 미확인인 것을 구분한다. 전체 완료 여부는 업무 계약의 필수 조건으로 결정한다.

## 전후 비교

가능하면 동일한 입력·모델·도구 조건에서 기존 방식과 수정된 방식을 비교한다. 조건이 바뀌었다면 변경 사항을 함께 기록하고, 개선 원인을 단정하지 않는다.

측정 후보는 필수 결과 충족 여부, 사실 오류, 사용자 수정 횟수, 실행 시간, 제공되는 경우 토큰·비용이다. 작업에 의미 있는 항목만 선택한다. 한두 예시는 동작 점검이며 일반적인 성능 보장이 아니다.

## 예시: Git 저장소 분석

입력은 저장소 경로와 기준 리비전, 산출물은 Markdown 보고서라고 가정한다.

- 정상 사례: 실제 진입점과 구성 파일을 근거로 실행 방법을 설명했는지 확인한다.
- 누락 사례: 테스트 설정이 없으면 미확인으로 보고하는지 확인한다. 테스트 통과를 지어내면 실패다.
- 회귀 사례: 모노레포 경로 처리 규칙을 수정한 뒤 기존 단일 패키지 사례도 다시 확인한다.

이 예시는 평가 방법의 설명이다. 실제 저장소를 실행한 결과나 측정 수치를 뜻하지 않는다.
