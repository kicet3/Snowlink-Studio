# AI 업무 위임 루프

업무를 재현하고 결과를 확인할 수 있는 스킬로 정리한다. 기존 지침과 도구를 먼저 활용하며, 사용자가 선택한 작업·환경·출력 형식을 유지한다.

## 요청에 맞는 범위

- **만들기:** 실제 업무를 조사하고 업무 스킬을 작성한다. 제작 요청만으로 실제 고객 데이터 처리나 예약 실행까지 시작하지 않는다.
- **실행하기:** 지정된 업무 스킬과 해당 실행에 필요한 자료를 읽고, 요청된 작업을 수행해 근거와 함께 보고한다.
- **고치기:** 실패한 입력·결과·기대를 대조하고, 원인에 해당하는 파일만 수정한다. 자료가 없으면 필요한 항목을 요청하고 진단 범위를 밝힌다.

이미 제공된 정보는 다시 인터뷰하지 않는다. 업무 하나를 정하기 어려울 때만 후보와 결과물을 확인한다.

## 업무 스킬 만들기

1. 기존 파일에서 목적, 입력, 산출물, 사용 도구, 완료 조건을 파악한다. 결과에 영향을 주는 미정 사항만 짧게 질문한다. 질문 개수나 인터뷰 시간은 고정하지 않는다.
2. 명확한 작업 단위를 정하고 [템플릿](assets/playbook-template.md)을 적용한다. 업무 설명·입력 계약·절차·예외·검증을 실제 내용으로 채운다. 미정 항목은 표시하고 실행 준비가 끝난 것으로 보고하지 않는다.
3. 기존에 검증된 스크립트·양식·참조 파일은 재사용한다. 반복 가능성과 효용이 확인된 자산만 추가한다. 결과물·실행 로그는 지침 파일과 구분한다.
4. 검사를 설계할 때 [증거와 평가 기준](references/evaluation.md)을 읽는다. 각 필수 산출물에 확인 방법과 실패 조건을 연결한다. 도구 실행 성공과 결과의 의미적 정확성을 구분한다.
5. 사용자가 지정한 위치에 업무 스킬을 작성한다. 위치가 없으면 프로젝트 관례 또는 해당 환경의 스킬 검색 경로를 따른다. 임의의 파일명으로 저장한 문서를 자동 발견되는 스킬이라고 부르지 않는다.

완성된 스킬에는 실제 사용 시점을 설명하는 `name`·`description`이 있어야 한다. 다른 환경의 스킬 규격을 요청하면 그 규격을 따른다. 자료가 길어지면 필요한 단계에서 읽을 참조 파일로 나눈다.

## 실행과 검증

- 실행 시작 시 입력 위치·버전과 출력 경로를 확인한다. 접근할 수 없는 입력을 다른 것으로 조용히 대체하지 않는다.
- 업무가 요구하는 검증을 수행한다. `통과 / 실패 / 미확인 / 해당 없음`을 구분하고 명령·파일 위치·원본 값 등 재확인 가능한 근거를 남긴다.
- 검증할 수 없는 항목을 통과로 취급하지 않는다. 실제로 실행하지 않은 테스트나 외부 전송을 완료했다고 쓰지 않는다.
- 기존 권한 범위의 국소적인 오류는 고치고 관련 검사를 재실행한다. 동일 오류가 반복되거나 외부 조건 때문에 진전이 없으면 무한 재시도 대신 원인과 남은 일을 보고한다.

작업 분업은 독립된 입력과 결과를 합칠 기준이 있을 때 검토한다. 이 스킬은 하위 에이전트 실행이나 외부 변경에 별도 권한을 부여하지 않는다. 현재 요청과 환경의 권한을 따른다.

## 실패에서 개선하기

원인을 **입력 / 절차 / 도구·참조 자료 / 검증** 중에서 근거로 판별한다. 증거가 부족하면 가설로 표시한다.

수정 기록에는 관찰한 실패, 변경한 규칙이나 도구, 재실행 결과를 남긴다. 검증 기준을 낮춰 통과시키지 않는다. 절차를 바꾼 경우 실패했던 사례와 기존에 성공한 관련 사례를 다시 확인한다. 한 번의 특이 사례를 모든 업무의 공통 금지 규칙으로 확대하지 않는다.

완료 응답에는 만들어진 파일, 실행한 범위, 검증 결과, 남은 미확인 사항만 필요한 만큼 정리한다. 성공률·시간 절감은 같은 조건에서 측정한 경우에만 보고한다.
